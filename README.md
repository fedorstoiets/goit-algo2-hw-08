## Структура проєкту

```text
goit-algo2-hw-08/
├── task_1.py
├── task_2.py
└── README.md

Завдання 1. LRU Cache
Реалізовано порівняння обробки великої кількості
запитів до масиву:
- без кешування;
- із використанням LRU-кешу.
Розмір масиву:
N = 100000

Кількість запитів:
Q = 50000

Підтримуються два типи запитів:
Range(left, right)
Update(index, value)

Реалізовані функції
range_sum_no_cache(array, left, right)update_no_cache(array, index, value)range_sum_with_cache(array, left, right)update_with_cache(array, index, value)


LRU-кеш має місткість:
K = 1000

Ключем кешу є пара:
(left, right)


Після Update видаляються всі кешовані діапазони,
які містять змінений індекс.
Інвалідація виконується лінійним проходом
по ключах кешу.
Тестування
95% Range-запитів вибираються із 30 часто
використовуваних діапазонів.
Приблизно 3% усіх запитів є операціями Update.
Програма вимірює час виконання з кешем та без кешу
і показує коефіцієнт прискорення.
Приклад:
Без кешу : 12.0600 с
LRU-кеш  : 4.7100 с (прискорення ×2.56)

Фактичний результат залежить від продуктивності комп'ютера.
Завдання 2. Sliding Window Rate Limiter
Реалізовано клас:
SlidingWindowRateLimiter


для обмеження кількості повідомлень користувачів.
Базові параметри:
window_size = 10 seconds
max_requests = 1

Для кожного користувача timestamps повідомлень
зберігаються у:
collections.deque


Методи
_cleanup_window()


видаляє timestamps, які вийшли за межі поточного
часового вікна.
can_send_message()


перевіряє можливість відправити повідомлення.
record_message()


перевіряє повідомлення та записує його timestamp,
якщо надсилання дозволене.
time_until_next_allowed()


повертає кількість секунд до моменту,
коли користувач зможе відправити наступне повідомлення.
Якщо після очищення вікна у користувача не залишається
повідомлень, запис користувача видаляється.
```
